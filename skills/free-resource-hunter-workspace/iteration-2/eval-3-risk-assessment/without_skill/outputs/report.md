# OpenRouter 风险评估：免费层可靠性与 Agent 工作流适用性

> 调研日期：2026-05-29
> 数据来源：OpenRouter 官方文档、第三方评测、用户社区反馈

---

## 一、结论先行

**可以用于原型验证和低风险 Agent 工作流，但不建议作为生产级 Agent 的唯一依赖。**

OpenRouter 的免费层是一个"足够用但不保证用"的层——它存在真实可用的免费模型，但存在吞吐限制、质量漂移、可用性波动、隐私策略漂移等风险。对于 agent 工作流（需要一致性和可预测性），这些风险比一般聊天场景更严重。

---

## 二、免费层现状（2026 年 5 月）

### 基本参数
| 项目 | 免费层 | 付费层 |
|------|--------|--------|
| 可用模型 | 25+ 个免费模型（Llama、Gemini Flash、Mistral 7B 等） | 300+ 个付费模型 |
| 速率限制 | 50 请求/天，20 请求/分钟 | 购买 $10+ 后升至 1000 请求/天，20 请求/分钟 |
| 信用卡 | 不需要 | 需要 |
| SLA | 无 | 无 |
| 可靠性 | Best-effort（尽力而为） | Best-effort（尽力而为） |
| 模型选择 | 随机分配（通过 `openrouter/free` 路由器） | 可精确指定 |

### 免费模型来源
免费模型由社区托管赞助商（主要是 Chutes AI）提供，OpenRouter 自身也在补贴部分成本。免费模型池会动态变化，今天可用的模型明天可能消失或被限流。

## 三、关键风险分析

### 风险 1：免费层缩水——已有先例

**2025 年 7 月，Chutes 对 OpenRouter 免费层实施限流。** Reddit r/JanitorAI_Official 社区 236 票的帖子记录了这一事件：Chutes 开始对 OpenRouter 的免费层（包括充值了 $10 的用户）进行限流，优先保障付费用户。这说明：

- 免费层的可用容量受上游赞助商控制，OpenRouter 并不完全自主
- 免费层的"稳定性"依赖第三方的商业决策
- **今天免费的模型明天可能被限流、降速，甚至从免费池中移除**

### 风险 2：平台整体稳定性不足

根据 2026 年 4 月的独立评测（ofox.ai）：

- **8 个月内发生了 3 次有记录的宕机**，每次 35-50 分钟
- 没有正式的 SLA（无服务等级协议，无宕机赔偿）
- 2026 年 2 月的两次宕机中，OpenRouter 返回了误导性的 `401 "User not found"` 错误，实际是平台基础设施故障（后已修复为 503）
- 附加延迟：25-40ms（对大多数交互式场景可接受，但对高频 agent 调用会累积）

**对于 Agent 工作流**：一个典型的 coding agent 每次任务可能发出 3-5 次 LLM 调用。如果 OpenRouter 宕机 35 分钟，整个 agent 完全不可用，没有回退机制。

### 风险 3：免费层质量漂移

- `openrouter/free` 路由器**随机选择**满足要求的免费模型，每次请求可能被路由到不同模型
- 输出质量、风格、推理能力会随请求变化
- 上游赞助商可能在高峰期将流量路由到低配硬件，导致输出质量下降
- **对于 Agent 工作流**：一致性是关键。如果 agent 的"计划-执行-验证"链条中每次调用的模型都不同，结果不可预测

### 风险 4：隐私政策漂移风险

OpenRouter 官方声明（2026 年 5 月确认）：
- 默认不存储 prompt 和 response
- 匿名抽样分类少量 prompt（用于模型排名统计，零数据保留策略）
- 存储元数据（token 数量、延迟等，不含内容）

**但存在隐患：**

1. **ToS 变更先例**：Skool 社区有用户报告 OpenRouter 更新了服务条款——如果启用了 prompt logging，OpenRouter 获得了对输入/输出数据进行商业使用的不可撤销权利（包括可能向分析合作伙伴出售匿名片段）。虽然默认关闭，但这表明平台对数据政策的态度可能随商业需要变化。

2. **免费层路由到不可控的上游提供商**：免费池包含的提供商可能变化，每个提供商有自己的数据保留和训练策略。你无法保证你的数据始终被路由到符合你隐私要求的提供商。

3. **BYOK（自带 Key）场景**：如果使用自己的 API key，OpenRouter 免费提供 100 万次/月请求路由，超出后收取 5% 费用。免费层的 BYOK 请求同样受上述隐私漂移风险影响。

### 风险 5：隐性费用陷阱（如果你最终需要升级）

如果你的 Agent 工作流从免费层"毕业"到付费层，需注意：

| 费用项 | 金额 | 备注 |
|--------|------|------|
| 信用卡充值手续费 | 5.5%（最低 $0.80/笔） | 小额充值实际费率远高于 5.5% |
| 加密货币充值手续费 | 5.0% | — |
| BYOK 超额费 | 超出 100 万次/月后收取 5% | Agent 工作流容易突破此限额 |
| 信用额度有效期 | 365 天后过期 | 未使用的额度将丢失 |
| 非美元卡汇率损失 | 额外 1-3% | Stripe 汇率转换 |

**场景计算**：一个有 50 名开发者的团队，每人每天 20 次 agent 运行，每次 4 次 LLM 调用 = 60 万请求/月。3 倍增长后 = 180 万请求/月，超出 100 万免费额度，产生约 $320/月的 BYOK 费用。

## 四、与直接使用 API 对比

| 维度 | OpenRouter 免费层 | 直接使用 API（如 Anthropic） |
|------|-------------------|---------------------------|
| 成本 | $0 | 按量付费 |
| 模型一致性 | 差（随机分配） | 好（精确指定） |
| 可用性保证 | 无 | 有（有 SLA） |
| 速率限制 | 50 请求/天 | 视套餐而定 |
| 数据隐私控制 | 有限（路由到不可控提供商） | 更可控 |
| 适合场景 | 原型验证、学习、低风险实验 | 生产环境 |

## 五、具体建议

### 适合用 OpenRouter 免费层的场景
- Agent 原型验证和快速迭代
- 内部工具、hackathon、教学演示
- 低频、非关键的自动化任务
- 评估哪个模型最适合你的 agent 架构

### 不适合用 OpenRouter 免费层的场景
- 用户面向的生产 Agent 服务
- 需要一致输出质量的工作流
- 处理敏感数据的场景
- 每天超过 50 次请求的 Agent 循环

### 如果决定使用，降低风险的措施

1. **设计 fallback 机制**：不要把 OpenRouter 作为唯一 API 入口。准备直接 API key 作为降级方案。
2. **锁 pin 特定免费模型**：使用 `:free` 后缀（如 `meta-llama/llama-4-scout:free`）而非依赖 `openrouter/free` 随机路由。
3. **监控实际路由**：检查响应头中的实际提供商，确保数据路由到符合你隐私要求的提供商。
4. **关闭所有数据日志**：在 Observability 和 Privacy 设置中关闭 prompt logging。
5. **设置请求预算告警**：如果使用 BYOK，在 80 万次时设置告警（100 万免费额度的 80%）。
6. **评估免费层用量上限**：50 请求/天对 Agent 工作流来说非常紧张。计算你的 agent 每天需要多少次调用，确认是否足够。

### 推荐策略

**分阶段使用**：
- **阶段 1（探索期 1-2 周）**：用 OpenRouter 免费层验证 agent 架构和 prompt 设计
- **阶段 2（稳定期）**：对关键路径使用直接 API（如 Anthropic Claude），非关键路径继续用 OpenRouter 免费层
- **阶段 3（生产期）**：全面切换到直接 API 或付费 OpenRouter（如果需要多模型路由），不要在生产中依赖免费层

---

## 六、总结

OpenRouter 作为 API 聚合平台本身是靠谱的——它解决了多模型统一接入的真实痛点。但它的**免费层**不适合成为 Agent 工作流的生产基础：

- 免费层受上游赞助商控制，有被限流/缩水的先例
- 没有 SLA，8 个月 3 次宕机
- 随机模型路由导致输出不一致
- 隐私策略可能随 ToS 变更而漂移
- 50 请求/天的限额对 Agent 工作流几乎不够用

**建议**：用它来快速原型验证，但为生产 Agent 准备直接 API 兜底方案。如果预算允许，直接使用 Anthropic/OpenAI API 获得更好的一致性和可控性。如果必须用 OpenRouter，使用付费层而非免费层。
