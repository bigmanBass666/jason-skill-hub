## 风险评估报告：OpenRouter 免费层可靠性与 Agent 工作流迁移风险

### 评估目标

用户计划将 agent 工作流从当前平台（NVIDIA NIM）切换到 OpenRouter，核心关注：
1. 免费层是否靠谱，会不会突然缩水或收费
2. 用于 agent 工作流的可行性
3. 整体风险评估

---

### 一、免费层变更历史：已发生过大幅缩水

**结论：已经缩过一次水了，而且幅度很大。**

| 时间 | 事件 | 详情 |
|------|------|------|
| 2025-04-09 | **免费额度腰斩** | 每日免费调用从 200 次骤降至 50 次（砍 75%），同时引入 $10 余额门槛：充值 $10+ 的用户每天可享 1000 次免费调用 |
| 2025-04-09 | **免费模型范围收窄** | 免费调用限制集中在 < 50 字短文本，复杂任务（长文本分析、多轮对话）被排除在免费额度之外 |
| 2026-02-01 | **openrouter/free 路由器上线** | 新增统一路由器，自动分配免费模型，但附带严格的速率限制（20 req/min, 50 req/day） |
| 2026-04-26 | **:free 模型数量下降** | CostGoat 统计显示 :free 模型从此前的 50+ 降至约 30 个 |

**风险信号**：OpenRouter 有过明确的"先给甜头再收紧"的先例。2025 年 4 月的调整直接将纯白嫖用户的可用性砍掉了 75%。虽然充值用户获得了更多额度（1000 次/天），但本质上是**从"免费可用"变成了"付费才有体感"**。

### 二、隐藏费用陷阱（你可能没注意的）

| 费用层 | 金额 | 触发条件 | 影响 |
|--------|------|----------|------|
| **信用卡充值手续费** | 5.5%（最低 $0.80/笔） | 每次充值 | 小额充值实际费率极高：充 $5 = 16%，充 $10 = 8%，充 $15+ 才降到 5.5% |
| **加密货币充值手续费** | 5% | 每次充值 | 比信用卡略低 |
| **BYOK 超额费** | 等效 OpenRouter 价格的 5% | 每月超过 100 万次 BYOK 请求 | Agent 工作流高频调用极易触发。1000 个 agent 每天 4 轮调用 = 2.4M/月，超出部分全部收费 |
| **Stripe 外币转换** | 额外 1-3% | 非美元信用卡 | 叠加平台费后实际 ~7-8% |
| **免费模型静默回退** | 全价 | 免费模型触发限流后自动路由到付费 provider | 最危险的隐藏费用：你以为在用免费模型，实际可能被静默切换到付费模型并产生费用 |
| **Credits 有效期** | 过期清零 | 充值后 365 天 | 未用完的余额不退 |

**Agent 工作流的关键风险**：免费模型有严格的速率限制（通常 20 req/min, 200 req/day）。Agent 工作流一天可能发起数百甚至上千次请求。一旦触发限制，OpenRouter 可能将请求**静默回退到付费 provider**，且不会明确告知。你在 response headers 里才能看到实际使用了哪个 provider。

### 三、服务稳定性：有记录的宕机

| 日期 | 时长 | 原因 | 影响 |
|------|------|------|------|
| 2025-08-28 | 50 分钟 | 数据库故障（OpenRouter 自身基础设施问题） | 全面不可用 |
| 2026-02-17 | 38 分钟 | 第三方缓存依赖故障，20% 请求失败 → 80-90% 失败 | 返回误导性的 401 "User not found" 错误（实际是基础设施故障） |
| 2026-02-19 | 35 分钟 | 同一缓存层再次故障 | 两天内第二次宕机 |

**关键问题**：
- **无 SLA**：OpenRouter 不发布正式的 SLA，没有可用性承诺，没有宕机赔偿
- **误导性错误码**：2026 年 2 月的宕机期间返回 401 错误，导致开发者排查 API Key 问题——实际是 OpenRouter 的基础设施出了问题（后已修复为 503）
- **延迟开销**：每次请求经过 OpenRouter 路由层增加 25-40ms 延迟
- 对于 agent 工作流，35-50 分钟的宕机意味着整个 agent 管道停摆

### 四、数据隐私与 ToS 风险

**默认状态（较安全）**：
- OpenRouter 默认**不存储** prompt 和 response
- 匿名分类采样使用零数据保留策略

**需注意的 ToS 变更**（2025 年 4 月引发社区争议）：
- 如果你**开启了 prompt logging**，OpenRouter 获得输入输出的**不可撤销的商业使用权**
- 这意味着理论上可以将匿名化的片段出售给第三方
- 社区反馈："这对发送机密或 NDA 保护内容的用户来说是重大变化"

**建议**：
- 确保 Observability 和 "OpenRouter Use of Inputs/Outputs" 两个开关都是关闭的
- 对于包含敏感代码或商业机密的 agent 工作流，这是一个实质性的风险点
- OpenRouter 支持 Zero Data Retention (ZDR) endpoints，可进一步降低风险

### 五、平台存续风险

| 维度 | 评估 | 详情 |
|------|------|------|
| **融资** | 低风险 | 2025 年 2 月种子轮 $12.5M（a16z），2025 年 4 月 Series A $28M（Menlo Ventures），总计 $40.5M，估值 $500M |
| **团队** | 中等 | 11-50 人，总部纽约，创始人 Alex Atallah（前 OpenSea CTO 联创） |
| **投资方** | 低风险 | a16z、Menlo Ventures、Sequoia Capital，均为顶级 VC |
| **商业模式** | 中等风险 | 按用量收费 + 5.5% 平台费，尚未盈利（典型的增长期创业公司） |
| **竞争** | 中等 | 面临 ofox.ai、ZenMux、CrazyRouter 等竞品，以及各模型厂商自建 API 的长期威胁 |

**结论**：短期（1-2 年）存续风险低。$40.5M 融资和顶级 VC 背书说明短期内不会倒闭。但长期来看，如果模型厂商持续优化自有 API 体验，中间路由层的价值可能被压缩。

### 六、迁移到 OpenRouter 用于 Agent 工作流的可行性评估

#### 优势
- **OpenAI 兼容 API**：迁移成本低，改 base_url 和 api_key 即可
- **397+ 模型**：一个 key 接入几乎所有主流模型，切换模型只需改一个参数
- **国内直连**：无需梯子
- **Agent SDK**：2026 年 4 月 27 日上线了官方 Agent SDK
- **Function calling 支持**：大部分模型支持 tool calling

#### 核心风险

| 风险 | 严重程度 | 说明 |
|------|----------|------|
| **免费层不够用** | 高 | 50 次/天对 agent 工作流远远不够（你可能一天需要 500+ 次调用）。要么充值 $10+（1000 次/天），要么按量付费 |
| **免费模型静默回退** | 高 | 免费模型限流后可能自动切换到付费模型，产生意外费用 |
| **模型质量不稳定** | 中 | 通过路由层访问的开源模型，质量可能不如直连 provider（load balancing 到低配硬件、模型版本漂移） |
| **无 SLA 保证** | 中 | 8 个月内 3 次宕机，对于生产级 agent 工作流有风险 |
| **5.5% 平台费** | 中 | 长期使用累计可观。$1000/月 = $55 额外费用 |
| **BYOK 超额陷阱** | 中 | 月请求超 100 万次后，即使用自己的 key 也要付 5% 费用 |

#### 与当前平台（NVIDIA NIM）对比

| 维度 | NVIDIA NIM | OpenRouter |
|------|-----------|-----------|
| 免费额度 | 40 RPM，无总用量上限 | 50 次/天（无余额），1000 次/天（$10+余额） |
| 模型数量 | 100+ | 397+ |
| Agent 稳定性 | 仅 Step 3.5 Flash 稳定 | 取决于具体模型，免费模型质量参差不齐 |
| 国内访问 | 需特殊方式 | 直连 |
| 费用 | 完全免费 | 5.5% 平台费 + 潜在付费模型费用 |
| SLA | 无（但属 NVIDIA 生态） | 无 |
| 迁移成本 | — | 低（OpenAI 兼容） |

### 七、结论与建议

**总体判定：需警惕**

OpenRouter 本身不是骗局，也不是不可用。但它**不适合纯免费重度使用**，特别是 agent 工作流场景。

**具体建议**：

1. **不要指望免费层支撑 agent 工作流**。50 次/天的限制对 agent 场景形同虚设。即使充值 $10+ 获得 1000 次/天，高频 agent 仍可能不够用。
2. **如果决定用，必须做好费用监控**。关闭免费模型的自动 fallback 到付费 provider 的能力，或者设置硬性的费用上限。否则一次 agent 重试风暴就可能产生意外账单。
3. **关闭所有数据共享开关**。确保 prompt logging 和 "OpenRouter Use of Inputs/Outputs" 都是 OFF 状态。如果你的 agent 处理敏感代码，这一点尤其重要。
4. **考虑混合策略而非全面迁移**：
   - 保持 NVIDIA NIM 作为主力（免费、额度充足）
   - 用 OpenRouter 作为补充（模型多样性、国内直连、特定模型需求）
   - 而非"全部切到 OpenRouter"
5. **如果要全面迁移，建议充值 $50+ 一次性加载**（降低单笔手续费到 5.5%），而非多次小额充值。
6. **BYOK 路线也有坑**：如果你用自己的 provider key 通过 OpenRouter 路由，月请求超 100 万次后仍然要付 5% 费用。Agent 工作流很容易触及这个上限。

**一句话总结**：OpenRouter 是一个优秀的模型聚合平台，但它从 2025 年起已经走上了"收紧免费层、引导付费"的路线。对 agent 工作流而言，它是一个**好用但不免费**的工具，而非一个可以长期白嫖的平台。建议混合使用而非全面依赖。
