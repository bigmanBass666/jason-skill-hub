# OpenRouter 免费层可靠性评估报告

> 调研日期：2026-05-29 | 调研方式：公开信息搜索（用户反馈、官方公告、第三方评测）

---

## 结论先行

**不建议在生产级 agent 工作流中依赖 OpenRouter 免费层。** 免费层已多次单方面缩水，且存在数据隐私隐患和平台费用叠加问题。付费层可用，但成本未必低于直连官方 API。

---

## 1. 免费层政策变动历史

### 2025 年 4 月 — 大幅缩水（已发生）

OpenRouter 于 2025 年 4 月 9 日宣布重大政策调整：

| 项目 | 调整前 | 调整后 |
|------|--------|--------|
| 每日免费调用次数 | 200 次 | 50 次（缩减 75%） |
| 免费模型适用范围 | 全部免费模型 | 限 < 50 字短文本生成，复杂任务（长文本、多轮对话）被排除 |
| 付费用户激励 | 无 | 账户余额 > $10 的用户每日 1000 次上限 |
| 并发限制（RPS） | 统一 | 按账户余额分层，余额少则低 |

来源：站长之家、知乎、CSDN 等多家中文科技媒体报道（2025-04-09）

### 2026 年 5 月 — 现状

- 免费层仍存在，但限制严格：**50 请求/天，20 请求/分钟**
- 免费层无 SLA、无 uptime 保证
- 429 错误（配额用尽）是常态，需等第二天自动重置

**结论：免费层缩水不是"会不会"的问题，而是"已经发生且可能继续"的问题。**

---

## 2. 平台稳定性

根据第三方评测（2026 年数据）：

- **过去 8 个月内发生 3 次平台级宕机**，每次 35-50 分钟
- 无官方 SLA 承诺（无论免费还是付费）
- 免费层无 uptime 保障，付费层同样无平台级 SLA

对于 agent 工作流来说，这意味着任务可能在执行中途因平台不可用而中断，且无法获得赔偿或补偿。

---

## 3. 费用结构（隐性成本）

OpenRouter 标榜"推理价格不加价"，但实际存在多层费用：

| 费用项 | 说明 |
|--------|------|
| **充值手续费** | 充值时收取约 5.5% 的平台费（Credit purchase fee） |
| **BYOK 手续费** | 自带 API Key 通过 OpenRouter 调用时，收取 5% 使用费 |
| **加密货币支付** | Coinbase 1% + OpenRouter 4% 手续费叠加 |

官方已宣布将取消 BYOK 的 5% 使用费，改为固定月费订阅（定价待定），但截至目前尚未生效。

**实际影响：** 第三方评测显示，OpenRouter 的真实成本比标价高约 5-25%（取决于使用方式），对于大规模 agent 工作流，这个差距会相当明显。

---

## 4. 数据隐私风险

这是最值得关注的问题：

### 默认数据收集
- OpenRouter **默认开启 prompt/completion 日志记录**
- 用户可以选择关闭日志，但关闭后无法享受 1% 折扣

### 服务条款争议
- OpenRouter 更新后的服务条款规定：如果保持日志开启，平台获得对 Inputs/Outputs 的**不可撤销商业使用权**
- 这意味着理论上可以将匿名化片段出售给第三方或分析合作伙伴
- 来源：社区用户反馈（skool.com 讨论组）

### 合规限制
- GDPR DPA（数据处理协议）仅对 Enterprise 层客户开放
- 无 HIPAA 合规认证
- 对于处理敏感数据的 agent 工作流，这是硬伤

**如果你的 agent 工作流涉及任何敏感信息（代码、业务数据、用户数据），必须关闭日志，且需要评估数据经由第三方中转的风险。**

---

## 5. Agent 工作流迁移的具体风险

| 风险项 | 影响 | 严重程度 |
|--------|------|----------|
| 免费层 50 次/天上限 | agent 任务量一大立即被限流 | 高 |
| 无 SLA / 3 次宕机 | 任务中断、workflow 失败 | 高 |
| 政策单方面变更 | 成本和可用性不可预测 | 中高 |
| 数据经第三方中转 | 增加攻击面、隐私合规风险 | 中（取决于数据敏感度） |
| 平台费叠加 | 实际成本可能高于预期 | 中 |
| 免费层并发限制低 | agent 并行任务受阻 | 中 |

---

## 6. 建议

### 不推荐场景
- 生产环境 agent 工作流（无 SLA + 限流是致命的）
- 涉及敏感数据的场景（隐私条款风险）
- 需要高并发或高频调用的场景（50 次/天远远不够）

### 可考虑场景
- 个人开发/测试阶段的低成本试错
- 偶尔调用、非关键路径的辅助功能
- 多模型对比测试（OpenRouter 的核心价值是聚合 300+ 模型）

### 推荐替代方案

| 方案 | 适合场景 | 优势 |
|------|----------|------|
| **直连官方 API**（Anthropic / OpenAI / Google） | 生产 agent 工作流 | SLA 保障、无中间层费、数据不经过第三方 |
| **BYOK 模式 + OpenRouter** | 需要多模型路由 | 用 OpenRouter 做路由，但用自己的 API Key，取消 5% 费后可接受 |
| **LiteLLM / 自建代理** | 技术能力强的团队 | 自主控制路由、无平台费、数据不出域 |

### 迁移策略（如果仍想用 OpenRouter）

1. **必须关闭 prompt 日志**（Settings > Data Collection），放弃 1% 折扣换取隐私
2. **至少充值 $10**，解锁更高的每日调用上限（1000 次）和并发
3. **设置用量告警**，监控费用异常
4. **准备好回退方案**，不要让 agent 100% 依赖单一中转平台
5. **定期检查服务条款更新**，OpenRouter 有单方面变更的先例
