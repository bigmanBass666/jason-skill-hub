# 超星学习通自动答题 Skill 改进计划

> 基于 2026-06-22 真实考试场景复盘

---

## 阶段一：DOM 摸底与诊断工具（前置能力）

### 1.1 新增「页面侦察」标准脚本

**当前问题：** 进入答题页后需要反复试探 DOM 结构，低效且容易遗漏信息。

**改进内容：**
- 在 SKILL.md 核心流程中新增一个独立的 `侦察阶段`
- 提供一个可直接复制执行的 JavaScript 侦察脚本，一次性返回：
  - 页面 URL 类型（`preview` / `test` / `dowork` / `look`）
  - 题目总数及各题型数量
  - 所有 `[role="radio"]` 元素的索引列表（标注字母选项映射）
  - 所有编辑器的 iframe 列表（标注尺寸、src、是否可写）
  - 可见按钮列表
  - 答题卡状态信息（已答/未答）

**产出：** 新增「侦察阶段」章节，放在「填写答案」之前。

### 1.2 新增「答案状态检测」脚本

**当前问题：** 填写后无法确认服务器是否已保存（`aria-checked` 不可靠）。

**改进内容：**
- 提供检测脚本，从多个维度判断是否选中：
  - 检查 `[aria-checked="true"]`
  - 检查 DOM 中是否有 `class` 包含 `selected` / `on` / `active` 的元素
  - 检查 `input[type="hidden"]` 的值
  - 检查页面上的"答题卡"区域显示的已答数量
  - 作为最后手段：截图对比

**产出：** 新增「答案状态检测」章节，放在「验证所有答案」之前。

## 阶段二：核心流程增强

### 2.1 重构导航识别（预览页 vs 考试页 vs 作业页）

**当前问题：** 所有流程图只针对作业（work），考试（exam）的 URL 路径不同，预览页需要先触发进入。

**改进内容：**
- 新增 URL 路由表：

| URL 模式 | 页面类型 | 操作 |
|----------|---------|------|
| `/exam/preview` | 考试预览页 | 先弹出"进入考试"对话框并点击 |
| `/exam/test/` | 考试答题页 | 直接答题 |
| `/exam/test/look` | 已交卷查看页 | 终止，提示已交卷 |
| `/work/dowork` | 作业答题页 | 直接答题 |
| `/work/list` | 作业列表页 | 先选择作业进入 |

- 每一步给出判断逻辑代码

### 2.2 选项点击策略降级链

**当前问题：** 当前只推荐 `[ref]` 点击，但 ref 是 Playwright snapshot 的虚拟属性，并非真实 DOM 属性。

**改进内容：**
- 将点击策略改为明确的四级降级链：

```
策略1: document.querySelector('[ref="eXXX"]')?.click()
  ↓ 失败
策略2: document.querySelectorAll('[role="radio"]')[索引].click()
  ↓ 失败
策略3: el.dispatchEvent(new MouseEvent('click', {bubbles: true}))
  ↓ 失败
策略4: 直接调用 onclick 函数
       el.onclick.call(el, {currentTarget: el})
```

- 每种策略给出适用场景说明

### 2.3 批量填写通用公式

**当前问题：** 示例代码是逐题填写，实际需要批量操作。

**改进内容：**
- 给出通用索引计算公式：

```javascript
// 单选题：每4个选项一组
const radioIndex = (qNum - 1) * 4 + optionOffset; // A=0, B=1, C=2, D=3

// 判断题：每2个选项一组，从单选的末尾开始
const judgeStartIndex = 单选题数量 * 4;
const radioIndex = judgeStartIndex + (qNum - 31) * 2 + isTrue ? 0 : 1;

// 填空题 iframe：按题目顺序对应 iframe 数组索引
```

- 给出多选题的选择公式（`多选按位或组合`）

### 2.4 UEditor 填写改进

**当前问题：** skill 只说了 `contentDocument.body.innerHTML = '<p>答案</p>'`，没考虑不同类型 iframe 的处理差异。

**改进内容：**
- 区分三种 UEditor 情况：

| iframe src 特征 | 访问方式 |
|-----------------|---------|
| `javascript:void(function(){...})` | 直接 `contentDocument.body.innerHTML` |
| `javascript:false` 或 `javascript:` | 直接访问，但需要先触发编辑器初始化 |
| 外部 URL（跨域） | `SecurityError`，需用 Playwright `browser_type` 打字 |

- 检测编辑器是否已初始化的方法
- 大段文本分段写入的注意事项

## 阶段三：新章节/模板

### 3.1 新增「考试模式」独立章节

**当前问题：** 整个文档只针对作业（work），考试（exam）场景完全没有覆盖。

**改进内容：**
- 新增「考试模式」章节，与现有「作业模式」并列
- 包含：
  - 考试 URL 格式说明
  - 进入考试（处理 `preview` → 弹窗 → `test` 的流程）
  - 分卷作答提示处理（"当前考试需按分卷顺序作答"弹窗）
  - 考试专用的验证逻辑

### 3.2 新增「侦测脚本」模板章节

- 放在填写步骤之前，作为一个独立的可复用模板
- 用户粘贴到 `browser_evaluate` 中即可执行
- 输出结构化的页面信息

### 3.3 新增「答案速查表」模板

- 提供 JSON 格式的答案映射模板
- 支持单选题/多选题/判断题三种题型
- 方便用户快速将外部答案转换为可执行的格式

## 阶段四：风险评估与边界场景

### 4.1 新增弹窗处理清单

**当前问题：** 考试过程中有多种弹窗需要处理（"时间耗尽已提交"、"作答时间已用完"、"确认交卷"等），skill 没有系统整理。

**改进内容：**
- 列出所有已知弹窗及其处理方式

### 4.2 新增交卷后验证流程

**当前问题：** 提交后不知道是否真正成功。

**改进内容：**
- 检测"交卷成功"文本
- 如果交卷后跳转到 `/look` 页面，读取分数信息
- 如果仍有未答题，给出警报

## 预计效果

改进完成后，技能在面对以下场景时的表现：

| 场景 | 当前 | 改进后 |
|------|------|--------|
| 考试预览页 → 答题页 | 卡住，需用户手动 | 自动检测并进入 |
| 选项点不中 | 反复重试无策略 | 四级降级链自动 fallback |
| 不熟悉页面结构 | 多次 snapshot 摸索 | 侦察脚本一次摸清 |
| aria-checked 不可信 | 误判为未选中 | 多维验证 |
| 作业 vs 考试混用 | 只有作业示例 | 两者皆有 |
| 跨域 iframe | 报错不知原因 | 有诊断和处理方案 |
